## 一、蜘蛛腿程序化动画（铁锈战争蜘蛛类单位的核心技术）★重点标记

**现象**：RW的蜘蛛类单位（蛛形机甲等）腿部关节联动、触地爬行，遇坡随地形，而不是播放固定走路帧。

**技术本质：程序化动画（Procedural Animation）= 两骨解析IK + 步态步进**，与RW引擎内部实现无关，是通用技法，我们完全可以自研：

### 落地方案（2D俯视角版，纯数学零依赖）

1. **腿结构**：每条腿两段（大腿L1、小腿L2），足端为世界坐标锚点，不跟随身体
2. **解析IK**（余弦定理，比FABRIK便宜）：
   ```
   给定髋部H（身体挂点）、足端F、腿长L1+L2：
   d = |HF| 截断到 (|L1-L2|+ε, L1+L2-ε)
   膝盖K = H + 旋 toward F 角度α, α由余弦定理求出
   膝盖弯曲方向 = 腿相对身体的外侧法线（预配置，左腿朝左弯右腿朝右弯）
   ```
3. **步进触发**：足端偏离"理想落点"超过阈值 `stepDist` 才迈步；迈步时足端在 0.08~0.12s 内**带弧线**插值到身体前方预测落点（预测=当前速度×步时×1.5，提前迈才不拖沓）
4. **步态分组**：8足分两组（对角交替），同组腿不能同时离地——迈步前检查"邻组腿全部着地"，防止全腿悬空漂移
5. **身体表现**：高度轻微起伏（正弦随步数）、被拉扯时向足端质心倾斜
6. **渲染**：腿画在车体层**下面**，先足后节；纯canvas路径绘制，无需贴图
7. **性能**：每腿每帧十几次三角函数，8腿×屏内200单位≈16万次运算/帧，TS毫无压力；**屏外单位跳过动画**（迷雾内也不算）
8. **数据驱动**：`def.spider = { legs: 8, L1, L2, stepDist, gait: [[0,3,5,6],[1,2,4,7]], bodyBob }`，加到兵种JSON即成蜘蛛单位

**参考**：[Seth Wright 程序化蜘蛛动画](https://sethwrightgamedev.com/project-spider-animation)、[Jettelly Unity蜘蛛行走](https://jettelly.com/blog/how-did-this-developer-make-a-procedural-spider-walk-in-unity)、[Alan Zucconi 程序化动画入门](https://www.alanzucconi.com/2017/04/17/procedural-animations)、[GameMaker 2D IK蜘蛛（Reddit）](https://www.reddit.com/r/gamemaker/comments/fra8wf/spider_walking_using_inverse_kinematics)

**建议时机**：M3 兵种扩展——做一个"蛛形机甲"（中型，8腿，高血量，近战震荡），视觉差异化直接拉满。

## 三、开源RTS引擎可借鉴技术

| 项目 | 语言/许可 | 偷什么 |
|---|---|---|
| [OpenRA](https://github.com/openra/openra) | C# / GPL | ①**Trait组件化架构**：单位=若干行为组件（移动/武装/可建造）组合，比我们现在的if-defId扩展性强——兵种过15个后值得重构；②**确定性锁步联机+录像回放**：指令流序列化，我们sim层已固定时间步+种子随机，天然接近，补"指令记录"即可回放 |
| [0 A.D.](https://github.com/0ad/0ad)（注意许可GPL） | C++/JS | **阵型系统**：编队按阵型表（方阵/楔形）分配槽位，我们issueMove的方阵偏移就是它的丐版；**单位微智能**：空闲自动觅敌/躲避投石区的状态机 |
| [Spring RTS](https://springrts.com/)（Beyond All Reason同底座） | C++/Lua | **流场寻路（Flow Field）**：目标点算一张全图流向场，海量单位查表移动，O(1)每单位——500人军团战的核心方案，M5性能卡如果A*预算不够就上这个；**Group移动AI** |
| [Stratagus/Wargus](https://github.com/Wargus/stratagus) | C++ / GPL | 经典2DRTS的资源回收（工人完工自动回采）、建造点校验、泰坦式生产队列——我们已相似实现，可对比细节 |
| [Warzone 2100](https://github.com/Warzone2100/warzone2100) | C / GPL | 部件化载具设计（底盘+武器+推进器自由组合）——魔法阵营的"召唤兽拼装"可以偷这思路 |
| [OpenSAGE](https://github.com/OpenSAGE/OpenSAGE) | C# | 将军类超武/将军技能树的UI-模拟交互范式 |

**用法提醒**：以上仓库几乎全部 GPL 系许可——**看代码学思路可以，复制粘贴不行**。落到本项目一律自己实现。

## 四、通用算法弹药库（本项目直接可用，无许可问题）

| 算法 | 解决什么 | 落地要点 | 时机 |
|---|---|---|---|
| 流场寻路 | 群体移动O(1)寻路 | BFS从目标点泛洪出int方向场，单位查表走 | M5 |
| 影响图(Influence Map) | AI战术决策 | 网格叠战力值，AI找敌薄弱侧翼 | M3~M4 |
| 势能场避障 | 群体避友军/障碍 | 目标吸引+障碍排斥合成向量（可替代部分分离推挤） | 备用 |
| 三角剖分寻路 | 大地图精确路径 | 备用，64×64格子用不上 | 备用 |
| 插值渲染 | 30Hz模拟60Hz画面平滑 | sim保留上一帧位置，渲染lerp——**当前60Hz直绘无需**，若将来模拟降频节能再上 | 备用 |
| 确定性锁步 | 联机/回放 | 指令序列化+固定步长+种子随机（已有） | M6后 |
| HPA分层寻路 | 超大地图A*加速 | 64×64不需要，128²以上再说 | 备用 |
| 屏外剔除/合批 | 渲染性能 | 视口外单位跳过drawImage；M5压力测试看数据 | M5 |

## 六、优先级建议（哈仔的判断）

1. **马上有用**：集结点渲染（M2）、攻击移动（M2）、命中白闪（M2）、指令队列（M2）
2. **内容期**：蜘蛛腿IK（M3新兵种）、道路地形（M3）、OpenRA式Trait重构（兵种>15个时）
3. **性能期**：流场寻路+屏外剔除（M5压力测试数据说话）
4. **远期**：锁步联机/回放（M6后）、运输/两栖/护盾（M4+）
