# 11 · 开局大厅与多人框架设计案

> 状态：**设计定稿，待开工**。对应里程碑 M4.3（v0.18）/ M4.4（v0.19）。
> 定位：把游戏从"一场决斗"升级成"一个战场"——槽位制开局大厅（地图/座位/阵营/队伍/难度），底下铺多玩家框架的地基。
> 方法论：大厅采用 RTS 标准槽位制（星际/帝国同款：每行一个座位，列=身份/阵营/队伍/难度）。只抄被验证过的。
> 依赖：阵营下拉的"晨曦王国"选项依赖 09/M4.0 落地；未落地时下拉占位（灰色"未实装"），框架照常先建。
> 【口味决议】AI 数量上限 **3**；**v1 不做 FFA**（队伍战 2 队起步）；**同队 AI 不协同**（各自为战，只共享视野与胜利）。

---

## 设计红线（六条）

1. **一切按槽位数组写**——`players`、AI、迷雾、日志全部座位化，全代码库禁止再出现写死的 `0|1` 玩家硬编码（清剿清单见五）
2. **标准档全 AI 零补贴**的诚实原则延续；1vN **不给玩家任何补偿**（想公平选 1v1，想被虐随便）
3. **v1 无 FFA、无局中外交**——队伍开局定死，中途不叛变
4. **同队 AI 不协同**——各自为战，只共享视野与胜利条件（v2 再议协同）
5. **中立 owner = 最大座位号 + 1**，动态分配，不再写死 2
6. **单人 1v1 默认体验不变**——老玩家打开大厅，默认就是现在这一局，无感升级

## 一、现状盘点

| 部件 | 状态 |
|---|---|
| 选择地图 | ✅ 已实装（v0.10：标准/群岛/随机+种子） |

## 二、大厅 UI（槽位制）

```
┌─ 选择战场 ────────────────────────────────────┐
│ 地图：[标准大陆▾]  种子：[123456]  [随机]      │
├─ 座位 ────────────────────────────────────────┤
│ 玩家   [人类]   阵营[钢铁联邦▾]  队伍[1▾]      │
│ AI-1   [电脑▾]  阵营[钢铁联邦▾]  队伍[2▾]      │
│          难度[困难▾]  性格[乌龟▾]              │
│ AI-2   [关闭▾]  （可开 1~3 个 AI 座位）         │
│ AI-3   [关闭▾]                                 │
├───────────────────────────────────────────────┤
│                  [开始征战]                     │
└───────────────────────────────────────────────┘
```

- 每行 AI 座位三件套：**阵营 / 队伍 / 难度+性格**——`resolveAIConfig` 改为按座位调用，管线现成
- 座位开关：人类（恒占座位0）/ 电脑 / 关闭
- 队伍下拉：1队 / 2队（v1 两队制；未来扩 FFA 再放开）

## 三、数据结构

```ts
interface SeatConfig {
  kind: 'human' | 'ai' | 'closed';
  faction: 'steel' | 'dawn';        // 09 落地前 dawn 灰显
  team: 1 | 2;
  difficulty: DifficultyId;         // 每座位独立
  personality: PersonalityId;       // 每座位独立
  custom?: Partial<AIConfig>;       // 自定义难度参数
}
```

- `AIController` 每座位实例化，`cfg` 来自各自座位
- **旧设置迁移**：localStorage 里的单 AI 设置（`sm_ai_settings`）自动迁移为 AI-1 座位默认值，无感升级
- 地图种子/变体结构照旧，挂在大厅状态里

## 四、多玩家框架重构（地基工程）

| 模块 | 改造 |
|---|---|
| `world.players` | 二元组 → `PlayerState[]`，长度=开启座位数 |
| 中立 owner | `OWNER_NEUTRAL` 由常量改为 `world.neutralOwner = 座位数`，动态分配 |
| 迷雾 | `fog: [Uint8Array, Uint8Array]` → 每座位一份；**共享视野=渲染时合并本队所有座位的已探区域** |
| 胜负 | "敌方 HQ+基地车绝迹"改为"**敌队所有座位** HQ+基地车绝迹"；本队任一座位存活即未败 |
| AI 敌我 | `foe = 1 - owner` 作废 → 敌对集合 = 队伍不同的所有座位；快照/选靶/续攻全部按敌对集合扫描 |

**`0|1` 硬编码清剿清单**（一次性还债）：`economy.ts` 收入循环、`world.addRes/mult` 的 `owner>1` 判定、`recomputePop`、`addLog` 的"我方/敌方"措辞（改按队伍名/座位色）、`minimap.ts` 配色分支、`combat` 索敌判定、`selftest` 的双基地假设。**改完立 selftest 锁死：全库 grep 不允许再现玩家数硬编码。**

## 五、队伍与外交（v1 最小集）

- `isAlly(a, b)` / `isEnemy(a, b)` 两个纯函数，全游戏一切敌我判定唯一入口（索敌/攻击指令/波次选靶/溅射误伤豁免）
- 同队：**不开火、不误伤、共享视野、共享胜负**；资源不共享、单位不可控（v2 再议支援操作）
- 同队 AI 各自为战：不做协同战术、不互相救援（红线4）；蛮族对两队一视同仁
- 局中叛变/投降：v2

## 六、地图多基地生成

- `mapgen` 支持 N 基地：标准图=轮转对称位（对角/三角/四角，按座位数取前 N）；随机图=种子布点+**基地间最小间距**+净空+连通三重校验（现版规则照抄，只是从 2 推广到 N）
- 蛮族营地/鹿狼群数量随地图利用面积微调（每新增基地 +1 营地），中立生态总量与地图 budget 挂钩
- 资源总量按基地数同步加密（矿脉团数 ∝ 座位数），保证每家开局经济公平

## 七、阵营选择

- 下拉框读阵营注册表（`FACTIONS`，09 落地后注册 `dawn`）；未落地时"晨曦王国（未实装）"灰显
- 同队同阵营镜像合法（2v2 钢铁 vs 钢铁=平衡最好审的组合）；混编合法；不限制
- AI 座位阵营同样可选，AI 数据表按阵营读取（09 的王国 weights 表）

## 八、结算画面

- 胜利方式（拆 HQ / 加冕——08/M3.4）+ **队伍结果**（胜方队标色）+ 座位列表（每人阵营/难度/性格/存活状态）
- 日志措辞全面座位化：`我方` → `蓝方/红方…`（按队伍配色）

## 九、selftest 用例（确定性）

1. 旧 1v1 回归：默认座位开局，与现有 selftest 全量等价（无感升级的保险）
2. 1v2：双 AI 敌对座位各自独立难度/性格生效（读各自 cfg 断言）
3. 2v2（3 AI 座位开满+玩家）：同队不开火、共享视野合并正确、敌队全灭判定胜利
4. 中立 owner 动态：4 座位时蛮族 owner=4，敌我判定不含中立
5. 多基地地图：三/四基地布点净空+连通校验
6. 全库无 `0|1` 玩家硬编码残留（grep 断言）
